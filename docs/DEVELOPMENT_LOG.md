# Development Log

## 2026-11-01 — v1.0.0 built from the Flutter template

**Phase 1 — audit.** Fresh `flutter create` project (counter template only).
Flutter 3.47.7 / Dart 3.13.5, Android SDK 36, JDK 21 (JBR), two Samsung
devices. SDK not upgraded; dependency versions resolved by `pub add` for this
SDK. Package id `com.zaid.hisnalmuslim` confirmed unused on Google Play.

**Phase 2 — planning.** Feature-first architecture, Riverpod 3, go_router 18
(stateful shell, 5 tabs), `SharedPreferencesWithCache` behind
`KeyValueStore`, bundled JSON content. Decisions recorded in
`docs/ARCHITECTURE.md`.

**Phase 3 — brand & design system.** Concept "the luminous fortress"
(khatam star + pointed arch + light). Icons/splash generated by
`tool/brand/generate_icons.py`; same geometry in Dart. Tokens, typography
(IBM Plex Sans Arabic, Amiri, Amiri Quran), components —
`docs/DESIGN_SYSTEM.md`.

**Phase 4/5 — content.** Sources: official hisnmuslim.com API (ar/en), book
footnote transcription (rn0x), evening wording (osamayy/azkar-db, verified
against the book's notes), Tanzil Quran text. Findings during verification:
- azkar-db's morning/evening lists include items *not* in the book → only
  official items are used.
- API `REPEAT` sometimes contradicts the book (e.g. حسبي الله … سبع مرات);
  a first heuristic over-fired on phrase-level counts (أستغفر الله ثلاثاً
  inside a longer dhikr; narrations like "أتوب في اليوم مائة مرة") → only a
  count *after* the quoted dhikr is applied.
- Chapter 86 in the API duplicates chapter 87's item → taken from the book
  transcription ("ولك", Ahmad 5/28).
- Chapter 27 footnotes (35 for 25 texts) aligned by a hand-reviewed table.
- Note: the file-writing tool decodes `\uXXXX` escapes into literal
  characters; regex escapes in `build_content.py` and
  `arabic_normalizer.dart` were restored with a byte-level script.
Result: 329 items, 323 referenced — `docs/content/CONTENT_VERIFICATION_REPORT.md`.

**Phase 4 — implementation.** All screens implemented (home, library,
category, reader, tasbeeh, favorites, search, reminders, settings, about,
privacy, sources, onboarding). Android: adaptive/themed icon, Android 12+
splash, notification receivers, desugaring, R8, release signing via
`key.properties`. iOS: bundle id, display name, launch screen, notification
delegate, encryption flag.

**Phase 6 — testing.** 68 automated tests. Defects found and fixed: circular
provider dependency (tasbeeh), overflows on 320-pt phones and at 200 % text,
WCAG contrast of two light tokens (computed with the WCAG formula), RTL bidi
of "/ 33", Windows Kotlin incremental-cache failure across drives
(`kotlin.incremental=false`). On-device QA on Android 10.
Reminder audit on device showed inexact alarms could be deferred ~10 h →
switched to exact-when-allowed (`SCHEDULE_EXACT_ALARM`) with fallback and an
in-app opt-in; verified `window=0`.

**Phase 7 — release prep.** Store texts (AR/EN, limits verified), privacy
policy, data safety, permissions audit, checklists, build instructions,
store graphics rendered from the real UI (`tool/store_assets`).
